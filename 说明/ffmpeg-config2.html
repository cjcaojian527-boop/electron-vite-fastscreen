FFmpeg fluent-ffmpeg 方法与参数配置指南

参数配置 (inputOptions / outputOptions)
实例方法 (run / kill / on 等)

本文档旨在详细解释 fluent-ffmpeg 库中 .inputOptions() 和 .outputOptions() 方法的常用参数及其用法。这些参数直接映射到 FFmpeg 命令行，用于精细控制音视频的输入读取和输出编码。

重要提示：

  • fluent-ffmpeg 的方法是链式调用，参数通常作为字符串数组传递。
  • 你需要对 FFmpeg 的命令行参数有基本的了解。
  • 某些参数可以在输入和输出中都使用（例如 -t、-r），但它们的作用在不同上下文中可能有所不同。

一、.inputOptions() 参数

这些参数影响 FFmpeg **如何读取和解释输入文件或设备**。它们通常在 FFmpeg 命令行中出现在 -i <input_path> 参数之前。

用法示例：

ffmpeg()
    .input('desktop')
    .inputFormat('gdigrab') // 或者 .fromFormat('gdigrab')
    .inputOptions([
        '-framerate 30',          // 设定输入捕获帧率为 30 FPS
        '-video_size 1920x1080', // 设定输入视频尺寸为 1920x1080
        '-draw_mouse 1'           // 捕获鼠标
    ])
    // ... 其他链式调用
    .run();
参数名 作用 用法示例 (在 inputOptions 中) 常见场景 注意事项
-f <format> 强制指定输入格式。 '-f gdigrab' 设备捕获 (如 gdigrab)，或处理无法自动识别格式的流。 当使用 inputFormat() 或 fromFormat() 时，通常不需要重复指定。
-ss <time> 从输入的指定时间点开始读取。 '-ss 00:01:30' (从1分30秒开始) 截取视频的某一段，或从视频中间开始处理。 时间格式可以是 HH:MM:SS 或秒数 ('90')。
-t <duration> 限制输入的持续时间（FFmpeg 只读取输入的前N秒/分钟）。 '-t 60' (只读取前60秒) 快速测试，或处理大型输入文件的部分。 与 outputOptions 中的 -t 区分：这里是限制**输入读取**的长度，不会直接决定最终输出时长。
-r <framerate> 设置输入捕获的帧率。 '-framerate 30' 屏幕录制、摄像头捕获等设备输入。 确保输入帧率与你的捕获能力匹配。过高的帧率可能导致掉帧。建议与输出帧率保持一致或合理转换。
-s <WxH> 设置输入视频的分辨率。 '-video_size 1920x1080' 屏幕录制时指定捕获区域分辨率。 并非所有输入设备都支持任意分辨率。如果未指定，通常会捕获设备的默认或最大分辨率。
-offset_x <x> (仅限 gdigrab) 捕获区域的 X 坐标偏移。 '-offset_x 100' Windows 桌面录制，录制部分屏幕。 需配合 -offset_y 使用。
-offset_y <y> (仅限 gdigrab) 捕获区域的 Y 坐标偏移。 '-offset_y 50' Windows 桌面录制，录制部分屏幕。 需配合 -offset_x 使用。
-draw_mouse 0|1 (仅限 gdigrab) 是否捕获鼠标指针 (0为否，1为是)。 '-draw_mouse 1' Windows 桌面录制。 默认为 1。
-show_region 0|1 (仅限 gdigrab) 是否显示捕获区域框 (0为否，1为是)。 '-show_region 0' Windows 桌面录制。 默认为 1。在录制时显示一个绿色的框。
-i audio="device_name" (仅限 dshow / avfoundation 等) 录制音频设备。 '-i audio="virtual-audio-capturer"' (Windows dshow) 屏幕录制时同时录制系统音频。 需安装并配置虚拟音频设备或选择正确的物理麦克风。需要额外的 addInput() 调用来添加音频输入流。

二、.outputOptions() 参数

这些参数影响 FFmpeg **如何编码、处理和生成输出文件**。它们通常在 FFmpeg 命令行中出现在所有输入参数和输出文件路径之间。

用法示例：

ffmpeg()
    // ... 输入配置
    .videoCodec('libx264')
    .outputOptions([
        '-crf 20',                // 核心：控制视频质量，20通常很清晰
        '-preset medium',         // 兼顾编码速度和文件大小的良好平衡
        '-pix_fmt yuv420p',       // 兼容性好的像素格式
        '-r 60',                  // 输出帧率与输入保持一致
        '-t 10'                   // 输出时长10秒
    ])
    .output('output.mp4')
    // ... 事件监听
    .run();
参数名 作用 用法示例 (在 outputOptions 中) 常见场景 注意事项
-t <duration> 限制输出视频的总时长。 '-t 10' (输出视频10秒) 所有转码/录制场景，限制输出文件长度。 与 inputOptions 中的 -t 区分：这里是限制**输出文件**的长度。
-c:v <codec> 视频编码器。 '-c:v libx264' 设置视频压缩方式。 也可以使用 videoCodec() 方法。确保你安装的 FFmpeg 支持该编码器。
-c:a <codec> 音频编码器。 '-c:a aac' 设置音频压缩方式。 也可以使用 audioCodec() 方法。
-crf <value> 视频质量 (Constant Rate Factor)。对于 libx264/libx265 最推荐。 '-crf 20' (值越小质量越高，文件越大) 高质量视频编码。 核心参数！ 范围通常是 0-51。23是默认值，18接近视觉无损。屏幕录制文字等细节多，推荐 18-22。**通常不与 -b:v 同时使用**。
-b:v <bitrate> 视频比特率。 '-b:v 2M' (2 Mbps) 精确控制文件大小。 与 -crf 互斥，不要同时设置。固定比特率可能导致在复杂场景下质量不足。
-b:a <bitrate> 音频比特率。 '-b:a 128k' 控制音频质量和文件大小。 例如 64k (低质量)，128k (中等)，192k (高质量)。
-preset <name> 编码速度预设。影响编码速度和压缩效率。 '-preset medium' (推荐平衡) 平衡编码速度和文件大小。 值有 ultrafast, superfast, fast, medium, slow, veryslow。越慢的预设压缩效率越高，但编码时间长。建议直接通过 outputOptions 传递，避免 preset() 方法可能的问题。
-pix_fmt <format> 像素格式。 '-pix_fmt yuv420p' 确保视频兼容性。 yuv420p 是最常见的兼容格式，适用于大多数播放器和 Web。
-r <framerate> 输出帧率。 '-r 60' 调整最终视频播放帧率。 务必与输入帧率保持一致或合理转换，否则可能导致视频不流畅或模糊。
-vf <filter_graph> 视频滤镜图。 '-vf scale=1280:-1' 视频尺寸调整、裁剪、水印等。 滤镜图语法复杂，需要查阅 FFmpeg 官方文档。-1 表示按比例自动调整。
-af <filter_graph> 音频滤镜图。 '-af volume=2.0' 音量调整、混音、去除噪音等。 滤镜图语法复杂。
-threads <num> 编码时使用的线程数。 '-threads 0' (使用所有可用线程) 加速编码。 0 表示使用所有可用线程。过多的线程可能会适得其反。
-map <stream_spec> 映射输入流到输出。 '-map 0:v' (映射第一个输入的视频流) 多个输入或选择特定流时。 精确控制要包含在输出中的视频、音频、字幕等流。
-n 不覆盖已存在的输出文件。 '-n' 防止文件被意外覆盖。 如果输出文件已存在，FFmpeg 会报错并退出。

使用建议：

  • **质量优先：** 对于屏幕录制，优先使用 -crf (如 -crf 20 或更低)。
  • **流畅度：** 确保输入和输出的 -r (帧率) 一致。
  • **兼容性：** 推荐使用 -pix_fmt yuv420p。
  • **调试：** 始终监听 'error' 事件，并打印 stdout 和 stderr 来获取 FFmpeg 详细日志。
  • **避免冲突：** 不要同时使用 .preset() 方法和 .outputOptions(['-preset ...'])。建议只使用后者。

本文档作为 fluent-ffmpeg 参数配置指南的补充，详细解释了 FfmpegCommand 实例上除了 .inputOptions() 和 .outputOptions() 之外的常用方法。

重要提示：

  • ffmpeg() 调用会返回一个 FfmpegCommand 实例，所有这些方法都在该实例上调用。
  • 许多方法支持链式调用，使得代码可读性更强。

一、进程控制与执行

方法名 作用 用法示例 返回/回调 注意事项
.run() 启动 FFmpeg 进程，执行构建的命令。 
command.run();
 无直接返回，异步执行。结果通过事件监听器处理。 这是命令链的终点，调用后 FFmpeg 进程开始运行。必须监听 'end' 和 'error' 事件。
.kill([signal]) 终止正在运行的 FFmpeg 进程。 
command.kill('SIGINT'); // 优雅终止
command.kill('SIGKILL'); // 强制终止
FfmpegCommand 实例本身。 'SIGINT' 通常会触发 FFmpeg 尝试完成当前文件写入。'SIGKILL' 是强制杀死，可能导致文件损坏。
.hasInput() / .hasOutput() 检查命令实例是否包含输入/输出。 
if (command.hasInput()) { ... }
 布尔值。 作为 Getter 使用，例如 command.hasInput。

二、事件监听

fluent-ffmpeg 通过事件来报告 FFmpeg 进程的生命周期和进度，这是处理异步操作的关键。

用法示例：

command
    .on('start', function(commandLine) {
        console.log('FFmpeg 命令已启动: ' + commandLine);
    })
    .on('progress', function(progress) {
        console.log('处理进度: ' + progress.timemark);
    })
    .on('end', function(stdout, stderr) {
        console.log('操作完成');
    })
    .on('error', function(err, stdout, stderr) {
        console.error('发生错误:', err.message);
        console.error('FFmpeg stdout:', stdout);
        console.error('FFmpeg stderr:', stderr);
    });
事件名 作用 回调参数 常见场景 注意事项
'start' FFmpeg 进程成功启动时触发。 commandLine (string)：实际执行的 FFmpeg 命令字符串。 记录日志，显示启动信息。 非常适合调试生成的 FFmpeg 命令。
'progress' 在 FFmpeg 处理过程中定期触发，报告进度。 progress (object)：包含 frames, currentFps, timemark, percent (对于实时流可能不准确) 等。 显示进度条，更新实时状态。 对于实时流，percent 字段可能为 NaN 或不准确。
'end' FFmpeg 进程成功完成所有操作时触发。 stdout (string), stderr (string)：FFmpeg 的完整标准输出和标准错误输出。 操作成功后的通知，清理资源。 确保文件已完整生成。
'error' FFmpeg 进程执行过程中遇到任何错误时触发。 err (Error), stdout (string), stderr (string)：错误对象及 FFmpeg 输出。 错误处理，调试问题。 至关重要！ 必须监听此事件。stderr 包含详细的错误日志。
'codecData' FFmpeg 读取到输入流的编解码器数据时触发。 data (object)：输入流的详细信息（如音频/视频流是否存在，时长，格式等）。 获取输入文件元数据，例如判断视频是否有音频流。 在 'start' 之前触发。
'stderr' 每当 FFmpeg 进程向标准错误输出一行数据时触发。 stderrLine (string)：FFmpeg 标准错误输出的单行文本。 实时监控 FFmpeg 的底层输出，进行更细粒度的调试。 通常用于高级调试。

三、获取 FFmpeg 信息

这些方法通常作为 ffmpeg 模块的静态方法调用，用于查询 FFmpeg 的能力。

方法名 作用 用法示例 回调参数 注意事项
ffmpeg.availableCodecs() 获取 FFmpeg 支持的所有编解码器列表。 
ffmpeg.availableCodecs((err, codecs) => {
    if (!err) console.log(codecs);
});
 err (Error), codecs (object) 异步方法，需要回调函数处理结果。
ffmpeg.availableFormats() 获取 FFmpeg 支持的所有格式列表。 
ffmpeg.availableFormats((err, formats) => {
    if (!err) console.log(formats);
});
 err (Error), formats (object) 异步方法。
ffmpeg.availableFilters() 获取 FFmpeg 支持的所有滤镜列表。 
ffmpeg.availableFilters((err, filters) => {
    if (!err) console.log(filters);
});
 err (Error), filters (object) 异步方法。
ffmpeg.getFfmpegPath() 获取当前配置的 FFmpeg 可执行文件路径。 
const path = ffmpeg.getFfmpegPath();
 字符串。 作为 Getter 使用。
ffmpeg.getFfprobePath() 获取当前配置的 FFprobe 可执行文件路径 (用于分析媒体文件)。 
const path = ffmpeg.getFfprobePath();
 字符串。 作为 Getter 使用。通常 `ffmpeg-static` 也会提供 `ffprobe`。

四、其他实用方法 (高级或便捷操作)

方法名 作用 用法示例 返回/回调 注意事项
.setFfmpegPath(path) 设置 FFmpeg 可执行文件的路径。 
ffmpeg.setFfmpegPath('/usr/local/bin/ffmpeg');
 无。 通常在应用启动时调用一次，设置全局路径。这是一个静态方法，直接在 ffmpeg 模块上调用。
.mergeToFile(outputPath, folderPath) 合并多个输入文件到一个输出文件。 
command.mergeToFile('output.mp4', '/tmp/');
 FfmpegCommand 实例。 通常用于简单的文件串联合并。
.seekInput(time) 在输入流中跳转到指定时间 (等同于 -ss 输入选项)。 
command.input('video.mp4').seekInput('00:00:10');
 FfmpegCommand 实例。 方便的链式调用，作用与 `inputOptions(['-ss ...'])` 相同。
.duration(time) 设置输出时长 (等同于 -t 输出选项)。 
command.duration(10); // 10秒
 FfmpegCommand 实例。 方便的链式调用，作用与 `outputOptions(['-t ...'])` 相同。
.size(WxH) 设置输出视频尺寸 (等同于 -s 输出选项)。 
command.size('640x480');
 FfmpegCommand 实例。 方便的链式调用，作用与 `outputOptions(['-s ...'])` 相同。
.autopad([color], [width], [height]) 自动填充黑边以适应输出尺寸。 
command.autopad(); // 自动填充
command.autopad('black'); // 填充黑色
 FfmpegCommand 实例。 通常与 .size() 结合使用。
.complexFilter(filters, [map]) 构建复杂的滤镜图。 
command.complexFilter([
    'overlay=10:10',
    'drawtext=text="Hello":x=10:y=10'
]);
 FfmpegCommand 实例。 **高级用法！** 用于实现画中画、多视频叠加、复杂文本/图形绘制等。需要深入了解 FFmpeg 滤镜图语法。
